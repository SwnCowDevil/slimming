# AI 食谱推荐与私人收藏架构设计

## 1. 目标与范围

本设计基于现有 `slimming` 微信小程序、FastAPI 后端和 TKA 食品成分数据。第一期提供：

- 27 条平台自有中式基础食谱。
- 基于 DeepSeek 官方 API 的个性化孕期食谱推荐。
- 条件筛选和自然语言需求两种推荐入口。
- 每次返回 3 道候选，并支持保留条件“换一批”。
- AI 推荐食谱的私人收藏、搜索、去重和归档。
- 孕期食材安全校验、TKA 营养计算与 AI 营养估算来源标记。

第一期不包含：

- 公共的用户贡献食谱库。
- 用户之间分享 AI 食谱。
- AI 医疗诊断、疾病治疗或药物建议。
- 通过第三方不明中转站访问模型。
- 运行时依赖 TheMealDB 免费 API。

## 2. 内容授权和来源

TheMealDB 免费 API 仅用于开发和学习，其条款要求公开发布应用时成为付费支持者。本项目不购买 TheMealDB 服务，因此生产环境不调用该 API，也不复制其图片、描述、做法或完整接口数据。

27 个中式菜名仅作为选题参考。平台基础食谱必须重新编写中文食材、克重、步骤和孕期注意事项，并使用项目自有、合法授权或自行生成的图片。版本化数据文件应保存图片和内容的来源说明。

相关依据：

- TheMealDB Terms of Use: https://themealdb.com/terms_of_use.php
- TheMealDB API: https://www.themealdb.com/api.php

## 3. 用户与内容边界

AI 食谱在收藏前是短期候选内容。收藏后才会写入永久数据库，并且只属于当前微信登录用户。

数据分为：

- `platform`：平台自有、已审核的 27 条基础食谱。
- `ai_temporary`：AI 临时推荐，有过期时间，不进入永久食谱搜索。
- `user_saved_ai`：用户收藏后持久化的私人食谱。

查询必须由服务端强制限定为：

```text
visibility = platform
OR owner_user_id = current_authenticated_user.id
```

服务端不信任前端提交的用户 ID。越权访问统一返回 404，不泄露资源是否存在。

## 4. 总体数据流

```text
食谱页
├─ 平台基础食谱
├─ 当前用户私人收藏
└─ AI 推荐入口
      ↓
筛选条件或自然语言需求
      ↓
FastAPI 推荐编排器
      ├─ 最小化读取孕期阶段、过敏原、忌口
      ├─ 调用 DeepSeek 官方 API
      ├─ 验证 JSON 结构和数值范围
      ├─ 执行孕期安全和过敏原规则
      ├─ 映射 TKA 并计算营养
      ├─ 标记无法匹配部分的 AI 估算
      └─ 计算内容指纹并去重
      ↓
展示 3 道通过校验的候选
      ├─ 换一批：保留条件并排除已展示指纹
      ├─ 收藏：二次校验后写入私人库
      └─ 记录饮食：确认食材与克重后写入
```

## 5. 小程序交互

食谱 Tab 沿用现有小程序的内容、卡片和视觉结构。顶部增加轻量 AI 推荐入口：

- 输入框：“告诉我今天想吃什么”。
- 示例：“孕中期，想吃清淡的鸡肉晚餐”。
- 操作：“帮我推荐”。

快捷筛选包括：

- 餐次：早餐、午餐、晚餐、加餐。
- 烹饪时长：15、30、60 分钟以内。
- 口味：清淡、酸甜、微辣、家常。
- 类型：高蛋白、轻素食、汤羹、主食。
- 已有食材和不想吃的食材：自由输入。
- 自然语言补充：任意一段需求。

孕期阶段、过敏原和档案忌口自动读取，不重复询问。

推荐结果每次最多 3 道，沿用原食谱卡片，增加：

- `AI 推荐`
- `营养为数据库计算` 或 `含 AI 估算`
- `已通过孕期规则检查`

页面支持“换一批”和“调整条件”。收藏后立即显示“已加入我的食谱”，并可从“我的收藏”筛选和顶部搜索访问。

## 6. 数据模型

### 6.1 `recipes`

在现有表上增加：

- `source_type`: `platform` / `ai`
- `owner_user_id`: 平台食谱为空，私人 AI 食谱为当前用户 ID
- `visibility`: `platform` / `private`
- `original_query`: 生成请求摘要
- `model_name`
- `prompt_version`
- `safety_rule_version`
- `nutrition_source`: `tka` / `mixed` / `ai_estimated`
- `nutrition_confidence`: `high` / `medium` / `low`
- `content_fingerprint`: 标题和标准化食材的指纹
- `content_status`: `published` / `archived`

`owner_user_id` 为外键并建立索引。私人食谱的指纹去重范围是单个用户，不阻止不同用户收藏相同内容。

### 6.2 `recipe_items`

在现有表上增加：

- `ingredient_name_zh`
- `original_measure`
- `grams`
- 可空的 `source_food_id`
- `nutrition_source`
- 可空的 AI 营养估算字段

TKA 无法匹配的食材允许收藏，但不得伪装成 TKA 数据。

### 6.3 `recipe_favorites`

- `user_id`
- `recipe_id`
- `created_at`

平台食谱收藏只创建关系。AI 候选收藏在一个数据库事务中创建正式食谱、食材明细和收藏关系。

### 6.4 `ai_recommendation_sessions`

- `id`
- `user_id`
- 筛选条件 JSON
- 自然语言需求
- 已展示的内容指纹
- 候选食谱 JSON
- `expires_at`
- `created_at`

默认保留 24 小时。未收藏候选过期后由清理任务删除。

## 7. AI Provider 边界

后端定义统一接口：

```python
class AiRecipeProvider:
    def generate_recipes(self, request: RecipeGenerationRequest) -> list[RecipeCandidate]:
        ...
```

第一期实现 `DeepSeekRecipeProvider`，但业务服务不引用 DeepSeek 具体 SDK 类型。配置由后端环境变量提供：

```text
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-v4-flash
AI_API_KEY=
```

`AI_MODEL` 是可覆盖的运行时配置，第一期默认使用当前官方支持的 `deepseek-v4-flash`。`AI_API_KEY` 必须由部署环境注入。API Key 不进入小程序代码，不写入版本库。生产环境只调用 DeepSeek 官方域名。

使用 DeepSeek JSON Output 获取结构化结果。由于官方说明 JSON Output 可能返回空内容，服务端必须校验、限次重试并支持降级。

相关依据：

- DeepSeek JSON Output: https://api-docs.deepseek.com/guides/json_mode/
- DeepSeek Rate Limit & Isolation: https://api-docs.deepseek.com/quick_start/rate_limit/
- DeepSeek Error Codes: https://api-docs.deepseek.com/quick_start/error_codes/

## 8. 模型输入与输出

### 8.1 最小化输入

只发送：

- 孕早期、孕中期或孕晚期，不发送预产期。
- 过敏原和忌口。
- 当次筛选和自然语言需求。
- 本会话已展示标题和内容指纹。
- 平台允许、限制和禁止食材规则。

不发送微信 openid、昵称、具体预产期、体重历史或其他无关健康数据。DeepSeek `user_id` 使用不包含隐私信息的随机标识。

### 8.2 候选结构

每道候选必须包含：

- 由后端生成的 `candidate_id`，仅在当前用户会话和过期时间内有效。
- 中文标题、简介、餐次和标签。
- 总份数和烹饪时间。
- 食材名称、数量、单位和估算克重。
- 分步做法。
- 过敏原。
- 每份热量、蛋白质、脂肪、碳水和膳食纤维估算。
- 推荐理由。
- 必须熟制的食材和处理要求。

## 9. 孕期安全流水线

AI 结果必须经过以下处理后才可返回前端：

1. JSON Schema 和字段范围校验。
2. 标题、食材和单位规范化。
3. 当前用户过敏原硬拦截。
4. 孕期禁止食材硬拦截。
5. 生食、半熟蛋肉、酒精、高汞鱼、未巴氏杀菌乳制品等规则检查。
6. 烹饪步骤与食材一致性检查。
7. TKA 食材匹配和营养计算。
8. AI 估算数值合理范围检查。
9. 与平台食谱、当前用户私人收藏和已展示结果去重。

命中风险的候选整道丢弃，不自动替换单个食材，也不向用户展示“带风险提示的推荐”。服务端最多补生成两次。仍不足 3 道时，返回实际通过数量并用基础食谱补位。

安全规则必须版本化，每次生成和收藏记录 `safety_rule_version`。

## 10. 营养数据

- 全部食材匹配 TKA：`nutrition_source=tka`。
- 部分匹配 TKA：`nutrition_source=mixed`。
- 无法匹配：`nutrition_source=ai_estimated`。

AI 估算必须显示“约”或估算范围，不得显示为权威数据库值。无法完整匹配的食谱可以收藏。记录饮食时，用户必须确认食材和克重，确认后重新计算并保存每项营养来源。

## 11. 收藏、去重和归档

收藏 AI 候选时：

1. 校验候选属于当前用户且未过期。
2. 重新执行安全校验。
3. 计算标准化标题与排序后食材的内容指纹。
4. 在当前用户范围查重。
5. 在单一数据库事务中写入食谱、食材和收藏关系。

重复收藏返回已有食谱。取消收藏平台食谱时只删除收藏关系；取消收藏私人 AI 食谱时将食谱标记为 `archived`，不物理删除，以保护已关联的历史饮食记录。

## 12. 搜索规则

搜索范围是平台食谱和当前用户未归档的私人食谱。排序优先级：

1. 标题精确或前缀匹配。
2. 食材名称匹配。
3. 标签匹配。
4. 生成需求摘要匹配。

接口支持 `scope=all|platform|favorites`。`favorites` 只返回当前用户收藏的平台食谱和私人 AI 食谱。

## 13. API 设计

### `POST /api/v1/ai/recipe-recommendations`

输入筛选条件和自然语言需求。返回：

- `session_id`
- 通过校验的候选食谱
- `mode`: `ai` / `fallback`
- 营养来源和提示
- `expires_at`

### `POST /api/v1/ai/recipe-recommendations/{session_id}/next`

沿用原条件换一批，排除当前会话已展示指纹。

### `POST /api/v1/ai/recipe-candidates/{candidate_id}/save`

二次校验并收藏 AI 候选。成功返回正式 `recipe_id`。重复收藏返回已有食谱。

### `GET /api/v1/recipes`

在现有筛选上增加：

- `query`
- `scope=all|platform|favorites`

### `POST /api/v1/recipes/{recipe_id}/record`

沿用现有食谱记录接口。含 AI 估算或未匹配食材时，要求先确认食材和克重。

### `DELETE /api/v1/recipes/{recipe_id}/favorite`

平台食谱删除收藏关系；私人 AI 食谱同时归档。

## 14. 错误处理与降级

- DeepSeek 超时、限流或不可用：返回平台基础食谱和私人收藏。
- 空内容或非法 JSON：内部限次重试，不向用户暴露技术错误。
- 安全规则拦截所有候选：引导调整需求并展示基础食谱。
- TKA 匹配失败：允许收藏，标记 AI 估算；记录前要求确认。
- 候选已过期：要求重新生成，不信任前端回传的完整食谱。
- 收藏重复：返回已有食谱。
- 越权访问：返回 404。

DeepSeek 429、500 和 503 使用有上限的短退避重试。401、402 和配置错误不持续重试。

## 15. 隐私、AI 标识和审核友好性

- 小程序只访问自有 FastAPI 后端，不直连模型。
- 使用 DeepSeek 官方 API，不使用第三方中转站。
- 不向模型发送微信身份、真实姓名或非必要健康数据。
- 界面显著标识 `AI 推荐` 和 `AI 营养估算`。
- 产品说明页公示实际模型名称和适用的备案或登记信息。
- 页面显示“AI 推荐仅供饮食安排参考，不替代医生建议”。
- 严重症状、药物、疾病或饮食障碍风险继续使用已有安全转介文案，不生成食谱。

## 16. 成本和防滥用

- 按用户和 IP 限制推荐及换一批频率。
- 对同一请求使用幂等键，避免重复调用和重复扣费。
- 短期会话缓存防止换一批重复。
- 记录模型、提示词版本、安全规则版本、耗时、重试和 token 用量，但日志不写入完整敏感输入。

## 18. 验收标准

1. 食谱页保留现有视觉和卡片风格。
2. 用户可通过筛选或自然语言获取最多 3 条安全候选。
3. 换一批保留条件，且同一会话不重复展示。
4. 任何命中孕期风险硬规则的候选不会展示或收藏。
5. AI 食谱收藏后只对当前用户可见，并可按标题、食材、标签和需求摘要搜索。
6. 无法完整匹配 TKA 的食谱可收藏，但营养估算必须显著标记。
7. 含 AI 估算或未匹配食材的食谱记录饮食前必须确认食材和克重。
8. DeepSeek 不可用时页面不空白，而是降级到基础食谱和私人收藏。
9. 生产运行不依赖 TheMealDB 免费 API 或第三方 AI 中转站。
